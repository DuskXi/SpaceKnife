「本机磁盘」页列出这台电脑的物理磁盘：机内的固态硬盘和机械硬盘、USB 盘、读卡器和存储卡。每块盘都写明它是什么盘、怎么接的、这条连接跑多快，以及上面有哪些卷。没扫描过的盘也在里面。

点开始页右栏最上面的「本机磁盘」卡片，或者在[命令面板](../command-palette/)里运行「本机磁盘」（输入 `disks`、`ssd`、`nvme`、`sata`、`usb` 也能找到）。它在单独的标签页里打开，打开时和点「刷新」时读取磁盘；页面不会自己变化，也不会弹出任何东西。

## 开始页上的卡片

卡片是这一页的摘要：有几块盘、总容量和可用空间、一条按存储类型分段的容量条，以及「最满」的卷和「最快」的链路。有发现时，右上角写着「N 条发现」（有需要留意的条目时用警示色和警示图标）。点卡片任何地方都会打开这一页。

## 汇总

页面上方是一块仪表盘：

- **物理磁盘**：有几块，按接口分别有几块。读卡器的空卡槽不算。
- **容量**：磁盘容量之和；环形计量显示你的卷已经用了多少，下面一行写出已用和可用。
- **卷**：本地卷有几个，其中几个 SpaceKnife 从扫描或快照里知道。
- **最快链路**：所有盘里最快的连接、它的带宽，以及是哪块盘。
- **容量构成**：按存储类型分段的容量条，从最快（NVMe SSD，最亮）到最慢（外接盘与存储卡）；下面的表写出每类有几块盘、多大、占多少。
- **发现**：值得知道的事，需要留意的排在前面：

| 发现 | 什么时候出现 |
|---|---|
| 「E:\ 已用 92%，只剩 38 GB」（需要留意） | 卷已用 90% 以上。80% 起也会列出，但不算需要留意。 |
| 链路比盘支持的慢 | 见[链路比它能跑的慢时](#链路比它能跑的慢时)。控制器能传的不到盘的 SATA 链路的四分之三时，算需要留意。 |
| 「… 不支持 TRIM」 | 不支持 TRIM 的 SSD：长期写入后可能变慢。 |
| 「D:\ 比 3 天前的快照多了 18 GB」 | 卷在最近两次完整快照之间增加（或减少）了 5 GB 以上，并且超过卷容量的 2%。 |

这里不会提醒你去扫描：没扫描过的卷只是照实显示。

## 每块盘显示什么

- **名称和容量**：磁盘报告的型号（型号里没有厂商时加上厂商）、存储类型（NVMe SSD、SATA SSD、机械硬盘、U 盘、存储卡……）、容量，以及系统给它的编号（Windows 上是「磁盘 3」，和「磁盘管理」里一致）。
- 「系统盘」标出装着系统卷的那块盘；「可移动」标出可以拔下或弹出的盘。
- **用了多少**：左边的环形计量显示这块盘上的卷用了多少，中间写着百分比。
- **接口**和**当前链路**：NVMe 加上它的 PCIe 链路（比如「PCIe 4.0 ×4 ≈ 7.9 GB/s」），SATA 加上速率（「SATA 6 Gb/s」），USB 加上当前连接的速率（「USB 480 Mb/s」「USB 5 Gb/s」）。系统同时报告了盘支持的最高速率时，还有一条计量把当前链路和它对比：「满速」，或者比如 PCIe 5.0 的盘插在 4.0 插槽上时的「最高速率的 50%」。
- **详细信息**：型号、厂商、序列号、固件、是否支持 TRIM，以及系统对它的称呼（`PhysicalDrive3`、`nvme0n1`、`disk2`）。序列号只留在你的电脑上，也只在这里折叠显示。

没有插入介质的盘（比如读卡器的空卡槽）只显示一行和它的盘符。

### 链路比它能跑的慢时

系统同时报告了磁盘支持的速率和实际速率时，链路下面会多一行说明：

| 你看到 | 意思 |
|---|---|
| 这块盘支持 PCIe 5.0 ×4，现在的插槽只给到 PCIe 4.0 ×4 | 盘比它所在的插槽快。换一个插槽或主板能给它更多。 |
| 设备支持 5 Gb/s，现在只以 480 Mb/s 连接 | USB 3 的盘或读卡器跑在 USB 2 的速度上：中间隔着 USB 2 接口、集线器或线材。 |
| 这块盘支持 6 Gb/s，现在以 3 Gb/s 连接 | SATA 接口或线材限制了速度。 |
| 经 PCIe 2.0 ×1 控制器（≈ 500 MB/s） | 这块 SATA 盘接在扩展卡的控制器上。控制器能传的比盘的 SATA 链路少时，连续读写会受限。 |

这些只是系统报告的事实，不是建议：盘够你用，就什么都不用做。

### 卷和容量条

每块盘下面是它上面的卷，按它们在盘上的顺序排列：盘符或挂载点、卷标、文件系统和已用多少（90% 起计量用警示色）。一块盘上有不止一个卷，或者有卷以外的空间（恢复分区、未分配空间）时，会多一条容量条，显示这块盘怎么划分；斜纹部分是不属于你任何一个卷的空间。

跨多块盘的卷（存储空间、LVM、RAID）在每块盘下面都会列出。不在任何已知磁盘上的卷，比如网络位置和虚拟卷，列在「其他位置」里。

## SpaceKnife 对一个卷知道什么

每个卷右边写着 SpaceKnife 从整卷扫描里知道的东西：

| 你看到 | 来自 |
|---|---|
| 「扫描于 2 小时前 · 1,234,567 个文件 · 1.9 TB」，加上最大的几个文件类别和顶层最大的文件夹 | 这个卷的扫描正开在某个标签页里。「查看」切到那个标签页。 |
| 「正在扫描 · 120,000 个文件」 | 这个卷的扫描还在进行。 |
| 「快照 3 天前 · … 个文件 · …」 | 没有打开的扫描时，这个卷最新的[快照](../snapshots-compare/)。「打开快照」打开它。 |
| 「还没有扫描过」 | 两者都没有。「扫描…」打开一个选好这个卷的开始页，你可以先看看选项。 |

这里只算整卷的扫描，扫描卷上的某个文件夹不算。

这个卷的扫描完成后，那一行下面会多一条分段条，显示最大的几个[文件类别](../tags-classes/)各占多少，再下一行写出顶层最大的几个文件夹。一个卷有两次以上完整快照时，会显示一条迷你折线：最近 12 次快照时它各有多大；旁边写出与上一次相比变化了多少，比如「比 3 天前的快照 +18.0 GB」。

## 这些信息从哪里来

SpaceKnife 只向系统询问，不需要管理员权限，也不从磁盘上读取任何数据。

| 系统 | 来源 |
|---|---|
| Windows | 每块盘的存储查询（型号、序列号、总线、TRIM、磁盘识别信息里的 SATA 速率、NVMe 识别信息）、它上方的设备树（NVMe 或 SATA 控制器的 PCIe 链路、USB 集线器报告的连接速率）以及每个卷所在的磁盘区段 |
| Linux | sysfs：`/sys/block`、PCI 设备的 `current_link_speed` 和 `current_link_width`、`/sys/class/ata_link/*/sata_spd`、USB 设备的 `speed` 和 `version`，以及 `/dev/disk/by-id` |
| macOS | `diskutil` 和 `system_profiler`（NVMe、SATA、USB） |

系统没报告的就留空，不去猜。具体来说：

- Windows 把 USB 3.2 Gen 2×2（20 Gb/s）报告成 10 Gb/s。
- Linux 只告诉 SATA 盘当前的速率，不告诉它最高支持多少；USB 3 设备接在更慢的接口上时，只能说它至少支持 5 Gb/s。
- Apple 芯片的 Mac 上，内置固态硬盘没有可报告的 PCIe 链路。
