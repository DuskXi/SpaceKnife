title: 更新与隐私
description: SpaceKnife 怎样发现、下载、校验和安装新版本，怎样调整或关闭更新检查，以及它发出的全部网络请求。
---

SpaceKnife 没有遥测，也不需要账户。它从网上取的东西只有 GitHub 上自己的发布列表，以及你点「一键下载」时的新版本和它的校验值。

## 更新检查

「设置 › 常规 › 更新 › 自动检查更新」打开时（默认），SpaceKnife 读取它在 GitHub 上的发布列表：

- 启动约 1 分钟后，如果上一次成功的检查已经超过 24 小时；
- 之后运行期间每 24 小时一次；
- 检查失败（没有网络、GitHub 繁忙）后，6 小时后再试，而不是 24 小时。

每次检查都带上已有列表的标记（ETag），列表没变时几乎没有开销。打开这个设置，或者改「提示哪些版本」，会立即检查一次。检查记下的东西（上一次检查、查到的最新版本、关掉过卡片的版本）保存在[数据文件夹](../data-locations/)的 `update.json` 里。

[命令面板](../command-palette/)里的「检查更新」随时可以检查，自动检查关掉了也能用。它的状态显示当前版本，或者查到的新版本。

### 提示哪些版本

「设置 › 常规 › 更新 › 提示哪些版本」：

| 选项 | 提示 |
|---|---|
| 「包括预览版」（默认） | 最新的版本，包括预览版 |
| 「只要正式版」 | 只提示不是预览版的版本 |

预览版是 GitHub 上标为预发布（Pre-release）的版本，或者版本号带预发布段的版本，比如 `0.4.0-beta.1`。草稿从不提示。选「只要正式版」时，要等出了更新的正式版才会提示。

## 新版本怎么提示

提示的力度取决于你落后多少。版本号逐段按整数比较，所以 `0.3.10` 比 `0.3.9` 新。

| 新版本不同的部分 | 例子 | 你会看到 |
|---|---|---|
| 最后一段，或者只差预发布段 | 0.3.1 → 0.3.2、0.4.0-beta.1 → 0.4.0 | 只有标题栏的徽章 |
| 中间一段（次版本） | 0.3.2 → 0.4.0 | 徽章，加上左上角的更新卡片 |
| 第一段（主版本） | 0.4.0 → 1.0.0 | 徽章，加上窗口内的更新对话框 |

- **徽章**在标题栏右侧，写着「更新 0.4.0」。悬停显示「SpaceKnife 0.4.0 可用（你在用 0.3.2）」；点它在下方打开更新卡片，点别处或按 <kbd>Esc</kbd> 关闭。
- **更新卡片**显示版本号、发布日期、你在用的版本、预览版的「预览版」标记、发布说明的开头和「查看完整说明」、适合你这种安装方式的文件和大小，以及「以后再说」「前往下载页」「一键下载」。
- 主版本的**对话框**里是同一张卡片，标着「大版本更新」。它打开时，背后的快捷键不起作用。

关掉卡片或对话框（关闭按钮、「以后再说」或 <kbd>Esc</kbd>）后，这个版本不会再自动弹出，重启后也一样；徽章保留。点徽章，或在命令面板里运行「查看更新」，可以再打开卡片。

## 下载与校验

「一键下载」按你的安装方式下载对应的文件，存进系统的「下载」文件夹：

| 你的安装方式 | 下载的文件 |
|---|---|
| Windows 安装包 | `SpaceKnife-<版本>-Setup-x64.exe` |
| Windows 便携版 | `SpaceKnife-<版本>-win-x64-portable.zip` |
| macOS | `SpaceKnife-<版本>-mac-arm64.dmg` 或 `…-mac-x64.dmg`，按你的 Mac |
| deb | `spaceknife_<版本>_amd64.deb` |
| rpm | `spaceknife-<版本>.x86_64.rpm` |
| AppImage | `SpaceKnife-<版本>-x86_64.AppImage` |
| Linux 便携版 | `SpaceKnife-<版本>-linux-x64-portable.tar.gz` |

下载时卡片显示进度和「取消」，徽章也会逐渐填满并显示百分比。下载完会校验文件：

- 把文件的 SHA-256 和同一个发布里公布的校验值（`SHA256SUMS*.txt`）比较，一致时卡片显示「SHA-256 校验通过」。
- 不一致的文件立即删除：「下载的文件与发布的 SHA-256 校验值不符，已删除」。
- 发布里有校验文件却读不到时，不下载。
- 发布里没有这个文件的校验值时，文件保留，并标注「这个版本没有发布校验和，文件未经校验」。
- 「下载」文件夹里已经有校验值正确的同一个文件时，直接用它，不再重新下载。

SpaceKnife 对不上发布文件的安装方式（比如从源码运行），「一键下载」不可用，卡片提示「这种安装方式请到发布页下载」。

## 安装

下载完成后，卡片会说明新版本怎么替换旧版本：

| 你的安装方式 | 按钮 | 结果 |
|---|---|---|
| Windows 安装包 | 「安装」 | SpaceKnife 退出并启动安装程序，由它替换旧版本。扫描数据和设置都会保留。 |
| macOS | 「安装」 | SpaceKnife 退出并打开磁盘映像。把 SpaceKnife 拖进「应用程序」替换旧版本，再[放行一次](../install/#macos)。 |
| deb、rpm | 「安装」 | SpaceKnife 退出，并用系统的软件安装器打开安装包。扫描数据和设置都会保留。 |
| 便携版 | 「在资源管理器中显示」（Windows）/「在文件管理器中显示」（Linux） | 退出 SpaceKnife 后解压，用新文件替换旧文件夹里的内容，但留下其中的 `data` 文件夹。 |
| AppImage | 「在文件管理器中显示」 | 退出 SpaceKnife，用新的 AppImage 替换旧文件（新文件已经设好可执行权限）。 |

点「安装」时如果还有扫描在进行，卡片会提示「还有扫描在进行，安装会中断它（已扫描的部分不会保存）」；点「仍然安装」继续。

SpaceKnife 不会在你没点的时候安装任何东西。它只会启动直接放在「下载」文件夹里、并且按你这种安装方式的发布文件命名的文件。

## 关闭更新检查

关掉「设置 › 常规 › 更新 › 自动检查更新」。之后除非你自己用「检查更新」或「一键下载」，SpaceKnife 不发出任何网络请求。之前检查到的版本仍可能显示徽章。新版本照常发布在 [Releases 页面](https://github.com/DuskXi/SpaceKnife/releases)，各种手动升级的方法见[安装与升级](../install/#升级)。

## 隐私

### 没有遥测

SpaceKnife 不发送任何关于你、你的电脑或你的文件的信息：没有使用统计、没有崩溃报告、没有标识符、没有账户。扫描、快照、标签和设置都留在你的电脑上，位置见[数据位置](../data-locations/)。

### 全部网络请求

全部发往 GitHub，而且只为了更新：

| 请求 | 什么时候 | 发送什么 |
|---|---|---|
| 发布列表，`api.github.com/repos/DuskXi/SpaceKnife/releases` | 自动检查，或「检查更新」 | 一个普通请求，带 `User-Agent: SpaceKnife/<版本>` 和已缓存列表的 ETag。没有令牌，没有 Cookie。 |
| 校验文件和发布文件，来自 GitHub | 只在你点「一键下载」时 | 同样的 `User-Agent` |

- 「前往下载页」和「查看完整说明」用你的浏览器打开 GitHub 上的发布页；SpaceKnife 本身不为它们请求任何东西。
- 请求遵循你的代理设置：常见的代理环境变量，Windows 和 macOS 上还有系统的代理设置。
- 和 GitHub 的连接用 HTTPS 证书验证。
- GitHub 对不带令牌的请求按地址限制次数。很多电脑共用一个出口地址时，检查可能暂时被拒（「GitHub 暂时限制了查询次数…」）；SpaceKnife 稍后会再试。
- 命令行（`spaceknife-backend scan`、`run`、`snapshot`）不发出任何网络请求。

### 留在你电脑上的

- 窗口和负责扫描的后端之间只用本机连接（回环地址，每次启动换一个随机令牌），其他电脑连不上。
- 日志文件和日志面板里有文件和文件夹的路径，比如无法读取的文件夹。
- 「复制诊断信息」（「设置 › 高级」）只复制到剪贴板。复制的内容包括设置文件和日志文件夹的路径，路径里通常有你的用户名；贴出去之前检查一下。
- 快照文件（`.sks`）里有扫描到的所有项的名称、大小和时间。分享快照等于分享你的文件夹结构；[导出](../export/)的报告也一样。
