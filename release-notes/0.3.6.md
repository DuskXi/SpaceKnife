## SpaceKnife 0.3.6 (pre-release)

A disk usage analyzer that shows what fills your drives, on Windows, Linux and macOS. SpaceKnife is an independent project inspired by SpaceSniffer and is not affiliated with SpaceSniffer or its author.

**This is a pre-release.** Windows and Linux builds are not code-signed; the macOS builds are ad-hoc signed, not notarized.

**This update fixes the freeze when changing the theme on Windows** and a few other ways SpaceKnife could stop responding, explains the colors of every coloring, and lets you hide folders you already know ([#26](https://github.com/DuskXi/SpaceKnife/issues/26)).

Every file was built and checked by GitHub Actions: {{build_runs}}.

Updates and the uninstaller remove only the files the installer put there (by the list it keeps next to them, `installed-files.txt`), and folders only once they are empty: a file of yours in the folder stays. ### What's new

- **Every coloring explains its colors.** Hover Classes, Flat, Time or Branch in the toolbar to see what each color means: the file classes, the time bands (under 1 day, 1 day – 1 week, 1 week – 1 month, 1 month – 1 year, over 1 year), or the top-level branches in view. Right-click one to open its settings: File classes for Classes, Appearance for the others.
- **The hover card says what a block's color stands for.** For "N small items" in Classes it names the class that holds at least half of their space ("Mostly Pictures"), or says the classes are mixed; in Time it gives how long ago the file was last modified; in Branch the top-level item it belongs to.
- **Hide the folders you already know** ([#26](https://github.com/DuskXi/SpaceKnife/issues/26)). List them in Settings › Visualization › Hidden folders, for example your music, movies or games. In a scan that holds any of them, Hide folders (H) appears in the toolbar (in the command palette: **Show/hide the folders listed in settings**): they take no room in the picture and the rest grows to fill it, until you turn it off. Zoomed into one, it shows as usual, and a folder's hover card says how much of it is in hidden folders. Nothing is hidden until you add a folder, and the scan itself still counts everything.

### Fixes

- **Changing the theme no longer freezes the window (Windows).** In 0.3.5 the window stopped responding the first time you switched between Light, Dark and Match system in a way that changed its colors, and it froze again at every start after that. If 0.3.5 is stuck for you, end it in Task Manager and get 0.3.6 from the table above (the update button can't be reached while the window is frozen): run the installer over it, or for a portable copy unpack the new zip and copy the old copy's `data` folder into it. 0.3.6 starts normally and keeps the theme you chose.
- **A whole-volume scan and the Disks page no longer hang while files change.** At the end of a scan of a whole drive, or when the Disks page showed an open scan of one, SpaceKnife could stop for good if the drive's free space changed in that moment (a busy system drive does so all the time): the scan stayed at "scanning" and the window stopped answering. Two rarer cases of the same kind are gone too, in the command palette and in the Delete basket while files change.
- **Waiting for administrator rights no longer stops SpaceKnife.** While Windows asked whether to allow the scan helper (or Linux asked for a password), the drive list and soon everything else waited with it.
- **Show in Explorer (Finder, file manager), Open and Open terminal here no longer freeze the window** when the item is on a network drive that went away or a disk that has to spin up first.
- **The start page checks a typed folder once.** It checked it again about three times a second for as long as the path stayed in the box, keeping network drives and sleeping disks awake.
- **In Scan details, the slider of a Custom disk load limit stays where you drag it** while a scan runs; progress updates used to put it back.

### Known limitations

- Nothing is code-signed or notarized yet (the macOS builds are ad-hoc signed).
- Snapshots saved since 0.3.5 (format 3) don't open in 0.3.4 and earlier: going back to one of those, you see only the snapshots it saved itself.
- No seamless update yet for the macOS dmg, deb and rpm: the card opens the disk image or package.
- From 0.3.4 on Ubuntu 23.10 and later, **Open the package** may not open the deb: 0.3.4 opens it from its hidden updates folder (`~/.local/share/SpaceKnife/updates`), which App Center (a snap) can't read. Download the deb from this page and open it, or run `sudo apt install ./spaceknife_0.3.6_amd64.deb`. 0.3.5 and later copy the package to Downloads before opening it.
- The ARM portables were built and tested on GitHub's ARM runners only, not yet on ARM hardware; the installers are x64 only.
- Not yet tried by hand: the update from 0.3.4 on a clean Windows 10 without the WebView2 Runtime, an all-users install with its administrator prompt, and opening the deb and rpm in the software centers of Ubuntu 22.04 and RHEL 9.
- On distributions that restrict unprivileged user namespaces (Ubuntu 23.10 and later), the AppImage and the portable `…-linux-<arch>-portable.tar.gz` may need `--no-sandbox`, as in 0.3.4; the deb and the small portable don't.
- On WinBtrfs, a scan that starts at (or inside) one of two folders whose names differ only in case reaches the other one, as do Explorer and copied paths; scan the folder that holds both.
- On macOS, the **Disks** page doesn't read NVMe disks' own health record yet (lifetime reads and writes, temperature, power-on time, life left); 0.3.4 did. The reads and writes since startup still show. It is planned for a later version.
- On macOS, the web view's own data (page storage and caches) is always kept in `~/Library/WebKit/io.github.duskxi.spaceknife`, for a portable copy and with `SPACEKNIFE_HOME` too: WKWebView takes no other folder. Settings, snapshots, logs and the cache stay where they were (a portable copy's in its `data` folder).

### 新功能

- **每种配色都有图例。** 鼠标停在工具栏的「类别」「扁平」「时间」「分支」上，就会看到每种颜色代表什么：各个文件类别、各个时间段（1 天内、1 天 – 1 周、1 周 – 1 个月、1 个月 – 1 年、1 年以上），或当前位置的各个顶层分支。右键直接打开相关设置：「类别」打开「文件类别」，其余打开「外观」。
- **悬停卡写出色块颜色的含义。** 类别配色下，「N 个小项」会写出占其中一半及以上空间的类别（「大部分是「图片」」），或说明是多种类别混合；时间配色下写出距上次修改多久；分支配色下写出属于哪个顶层分支。
- **隐藏你已经了解的文件夹**（[#26](https://github.com/DuskXi/SpaceKnife/issues/26)）。在「设置 › 可视化 › 隐藏的文件夹」里列出它们，比如音乐、影片、游戏。扫描里有其中的文件夹时，工具栏会出现「隐藏文件夹」（H；命令面板里是「显示/隐藏设置里列出的文件夹」）：它们不占画面，其余的块放大填满，关掉开关就回来。放大进其中一个时它照常显示，文件夹的悬停卡会写出其中有多少在隐藏的文件夹里。不添加就什么都不隐藏，扫描本身照样统计全部内容。

### 修复

- **切换主题不再让窗口卡死（Windows）。** 0.3.5 在浅色、深色和「跟随系统」之间切换时，只要窗口颜色真的变了，第一次就会停止响应，之后每次启动也都会卡住。如果你的 0.3.5 已经卡住：在任务管理器里结束它，再从上面的表里下载 0.3.6（窗口卡住时点不到更新按钮）：安装版直接用安装包覆盖安装；便携版解压新的 zip，把旧副本的 `data` 文件夹复制进去。0.3.6 能正常启动，并保留你选的主题。
- **整卷扫描和「本机磁盘」页不再在文件变化时卡死。** 扫描整个磁盘结束时，或「本机磁盘」页显示一个打开着的整卷扫描时，如果那一刻磁盘的可用空间变了（繁忙的系统盘随时都在变），SpaceKnife 可能从此停住：扫描一直显示「扫描中」，窗口不再响应。同类但更少见的两处也修好了：文件变化时的命令面板和删除篮。
- **等待管理员授权时不再卡住整个程序。** Windows 询问是否允许扫描助手（或 Linux 要求输入密码）期间，磁盘列表会跟着等待，很快其他功能也会停住。
- **「在资源管理器中显示」（访达、文件管理器）、「打开」和「在此打开终端」不再让窗口卡住**，即使对象在已经断开的网络盘上，或在需要先唤醒的硬盘上。
- **起始页对输入的路径只检查一次。** 以前只要路径还留在输入框里，就会每秒检查约三次，让网络盘和休眠的硬盘一直醒着。
- **扫描进行中，「扫描详情」里「磁盘负载上限」选「自定义」时，滑块会停在你拖到的位置**，不再被进度更新拉回原处。

### 已知限制

- 都还没有代码签名或公证（macOS 版是 ad-hoc 签名）。
- 0.3.5 起存的快照（第 3 版）0.3.4 及更早的版本打不开：退回这些版本时只看得到它们自己存的快照。
- macOS 的 dmg 和 deb / rpm 仍没有「无缝更新」：卡片会打开磁盘映像或安装包。
- 在 Ubuntu 23.10 及以后从 0.3.4 更新时，「打开安装包」可能打不开 deb：0.3.4 从它隐藏的 updates 文件夹（`~/.local/share/SpaceKnife/updates`）打开，App Center（snap）读不到那里。请在本页下载 deb 再打开，或运行 `sudo apt install ./spaceknife_0.3.6_amd64.deb`。0.3.5 起会先把安装包复制到下载文件夹再打开。
- ARM 便携版只在 GitHub 的 ARM 运行器上构建和测试过，还没在 ARM 真机上试过；安装包只有 x64。
- 还没有人工试过的：在没有 WebView2 Runtime 的干净 Windows 10 上从 0.3.4 更新、为所有用户安装时的管理员授权提示，以及在 Ubuntu 22.04 和 RHEL 9 的软件中心里打开 deb、rpm。
- 在限制非特权用户命名空间的发行版上（Ubuntu 23.10 起），AppImage 和便携版 `…-linux-<架构>-portable.tar.gz` 可能要加 `--no-sandbox`，和 0.3.4 一样；deb 和小巧的便携版不用。
- WinBtrfs 盘上两个只差大小写的文件夹，从其中一个（或它里面的文件夹）开始扫描，到达的是另一个，资源管理器和复制出去的路径也一样；请扫描包含两者的文件夹。
- macOS 上「本机磁盘」还读不到 NVMe 盘自己的健康记录（累计读写、温度、通电时间、剩余寿命），0.3.4 能读；开机以来的读写照常显示。计划在以后的版本补上。
- macOS 上网页视图自己的数据（页面存储与缓存）总在 `~/Library/WebKit/io.github.duskxi.spaceknife`，便携版和设了 `SPACEKNIFE_HOME` 时也一样：WKWebView 不接受指定的文件夹。设置、快照、日志和缓存仍在原来的位置（便携版在它的 `data` 文件夹里）。
