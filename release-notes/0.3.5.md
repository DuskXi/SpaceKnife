## SpaceKnife 0.3.5（预发布版）

SpaceKnife 是看清磁盘被什么占满的硬盘占用分析工具，支持 Windows、Linux 和 macOS。它受 SpaceSniffer 启发，是独立开发的新项目，与 SpaceSniffer 及其作者没有任何关联。[官网](https://spaceknife.kaltsit.dev/zh/) · [文档](https://spaceknife.kaltsit.dev/zh/docs/)

**这是预发布版**：Windows 和 Linux 版没有代码签名，macOS 版是 ad-hoc 签名，未经公证。

**这一版整个重写了**：后端从 Python 换成 Rust，界面换成 Vue：Windows 和 macOS 的便携版、新增的 Linux 轻量便携版、deb 和 macOS 版的窗口用 Tauri 2，Windows 安装包、rpm、AppImage 和沿用 0.3.4 名字的 Linux 便携版用精简的 Electron 外壳。功能和界面与 0.3.4 相同，变的是底下的程序和命令行程序的名字。

所有文件都由 GitHub Actions 构建并检查：{{build_runs}}。

- **校验和**：`SHA256SUMS.txt`（安装包）、`SHA256SUMS-portable-<目标>.txt`（便携版）、`SHA256SUMS-tauri-linux-<架构>.txt`（Linux 轻量便携版）和 `SHA256SUMS-mac-<架构>.txt`（dmg 与 macOS 便携版）随发布附带。

### 有什么变化

- **后端用 Rust 重写，跑在应用里面**：扫描、存储、过滤、布局、监控、导出和文件操作都换成了 Rust，服务端直接在应用进程里启动，不再另外带一个冻结的 Python 后端，也不再启动第二个进程。<!-- TODO: confirm 启动时间、内存的实测数字 -->
- **界面用 Vue 重写，有两个外壳**：便携版、deb 和 macOS 版用 Tauri 2，界面跑在系统自带的 WebView 里（Windows 上的 WebView2、macOS 上的 WKWebView、Linux 上的 WebKitGTK），不再打包一整个 Chromium，下载更小，占的内存也更少。Windows 安装包、rpm（RHEL 9 没有 WebKitGTK 4.1）和 AppImage 用精简的 Electron 外壳，界面是同一份。<!-- TODO: confirm 安装包大小和内存的前后对比 -->
- **命令行程序 `spaceknife-cli`**：和应用装在一起（Windows 在安装目录里，deb / rpm 在 `/usr/bin`，macOS 在 `SpaceKnife.app/Contents/MacOS`，便携版在程序旁边）；0.3.x 时应用旁边的程序叫 `spaceknife-backend`。子命令：`scan`（扫描并列出占用）、`run`（SpaceSniffer 风格的命令序列）、`snapshot list` / `snapshot show`（查看保存的快照）、`serve`、`headless`、`version`。
- **无头模式改成 `spaceknife-cli headless`**：`spaceknife-cli headless [--listen <地址>] [--yes] [--tls-cert 证书 --tls-key 私钥] [--ui 目录]`，在浏览器里使用 SpaceKnife；页面和 WebSocket 由同一个地址提供。0.3.x 的 `--headless`、`--listen <地址>` 写法仍然认，放在参数里的任何位置都行，`SpaceKnife --headless …` 照样启动无头模式（Windows 的终端里由应用旁边的 `SpaceKnife.com` 启动 `spaceknife-cli` 并等它结束；不带这些参数时它和 0.3.x 一样打开窗口、等窗口关掉）；便携版的无头模式和 0.3.x 一样把数据存在 `data` 里。<!-- TODO: confirm 安装包里是否带上了 headless 要用的 ui 文件夹 -->
- **设置和数据还在原来的位置**：设置、文件类别、归类的文件夹、记住的标签、命令面板的最近记录、更新记录和日志仍放在原来的文件夹里（Windows `%LOCALAPPDATA%\SpaceKnife`、macOS `~/Library/Application Support/SpaceKnife`、Linux `~/.config/SpaceKnife` 和 `~/.local/share/SpaceKnife`），0.3.5 接着用；macOS 上设了 `XDG_DATA_HOME` / `XDG_CONFIG_HOME` / `XDG_CACHE_HOME` 的，和 0.3.x 一样到那里找。0.3.x 轮转下来的旧日志（`logs/spaceknife.<时间>.log`）在第一次启动时删掉。读不了的 `classes.json` / `class_folders.json` 不会被覆盖：下次保存时改名留在原处（`classes.unreadable-<时间>.json`）。Tauri 版窗口自己的文件（主题、WebView 的数据）不放在 Electron 的配置文件夹里，第一次启动时沿用 0.3.4 选的主题；Electron 外壳仍放在 0.3.4 的位置。
- **0.3.x 的快照照样能用**：0.3.x 存的快照（第 2 版）不用转换就能打开、对比，也出现在「最近」和对比列表里；0.3.5 新存的快照是第 3 版。自动保存的保留规则（最近 10 份，更早的每周留一份）也算上 0.3.x 的快照；读不了的快照文件（损坏的、更新版本的）从不删除。

### 修复

- **「在终端中打开」可能执行文件夹名的一部分**（Windows）：文件夹名里有 `&`、`^`、`%` 或括号（例如 `x&calc`）时，0.3.4 把名字交给命令提示符，后半段会被当成命令执行。现在直接启动终端，从不经过 shell。
- **命令行输出到 NUL**：`scan` 的输出送到 `NUL`（命令提示符里的 `> NUL`、Git Bash 里的 `>/dev/null`）时会报错退出、不存快照；现在照常完成并保存快照。
- **命令行的英文单数**：有一个文件夹读不了的扫描写「1 folder couldn't be accessed」，`snapshot list` 写「1 snapshot in …」，`snapshot show` 写「· 1 item ·」。感谢 @swastiktawate（[#9](https://github.com/DuskXi/SpaceKnife/pull/9)）。

### 已知限制

- 都还没有代码签名或公证（macOS 版是 ad-hoc 签名）；deb 还没在干净的 Ubuntu 22.04 上测过。
- 0.3.5 存的快照（第 3 版）0.3.x 打不开：退回 0.3.x 时只看得到它自己存的快照。
- macOS 的 dmg 和 deb / rpm 仍没有「无缝更新」：卡片会打开磁盘映像或安装包。
- ARM 便携版只在 GitHub 的 ARM 运行器上构建和测试过，还没在 ARM 真机上试过；安装包只有 x64。
- WinBtrfs 盘上两个只差大小写的文件夹，从其中一个（或它里面的文件夹）开始扫描，到达的是另一个，资源管理器和复制出去的路径也一样；请扫描包含两者的文件夹。
