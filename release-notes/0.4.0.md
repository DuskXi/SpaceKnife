## SpaceKnife 0.4.0（预发布版）

SpaceKnife 是看清磁盘被什么占满的硬盘占用分析工具，支持 Windows、Linux 和 macOS。它受 SpaceSniffer 启发，是独立开发的新项目，与 SpaceSniffer 及其作者没有任何关联。[官网](https://spaceknife.kaltsit.dev/zh/) · [文档](https://spaceknife.kaltsit.dev/zh/docs/)

**这是预发布版**：Windows 和 Linux 版没有代码签名，macOS 版是 ad-hoc 签名，未经公证。

**这一版整个重写了**：后端从 Python 换成 Rust，窗口从 Electron 换成 Tauri 2 + Vue。功能和界面与 0.3.4 相同，变的是底下的程序、安装包的文件名和命令行程序的名字。

所有文件都由 GitHub Actions 构建并检查：{{build_runs}}。

### 有什么变化

- **后端用 Rust 重写，跑在应用里面**：扫描、存储、过滤、布局、监控、导出和文件操作都换成了 Rust，服务端直接在应用进程里启动，不再另外带一个冻结的 Python 后端，也不再启动第二个进程。<!-- TODO: confirm 启动时间、内存的实测数字 -->
- **窗口用 Tauri 2 + Vue 重写**：界面用系统自带的 WebView（Windows 上的 WebView2、macOS 上的 WKWebView、Linux 上的 WebKitGTK），不再打包一整个 Chromium，下载更小，占的内存也更少。<!-- TODO: confirm 安装包大小和内存的前后对比 -->
- **命令行程序 `spaceknife-cli`**：和应用装在一起（Windows 在安装目录里，deb / rpm 在 `/usr/bin`，macOS 在 `SpaceKnife.app/Contents/MacOS`，便携版在程序旁边），替代原来的 `spaceknife-backend`。子命令：`scan`（扫描并列出占用）、`run`（SpaceSniffer 风格的命令序列）、`snapshot list` / `snapshot show`（查看保存的快照）、`serve`、`headless`、`version`。
- **无头模式改成 `spaceknife-cli headless`**：`spaceknife-cli headless [--listen <地址>] [--yes] [--tls-cert 证书 --tls-key 私钥] [--ui 目录]`，在浏览器里使用 SpaceKnife；页面和 WebSocket 由同一个地址提供。原来的 `--headless`、`--listen <地址>` 写法仍然认，但要交给 `spaceknife-cli`，不再是 `SpaceKnife --headless`；Windows 上也不再需要 `SpaceKnife.com`。<!-- TODO: confirm 安装包里是否带上了 headless 要用的 ui 文件夹 -->
- **设置和数据还在原来的位置**：设置、文件类别、归类的文件夹、标签、命令面板的最近记录和日志仍放在原来的文件夹里（Windows `%LOCALAPPDATA%\SpaceKnife`、macOS `~/Library/Application Support/SpaceKnife`、Linux `~/.config/SpaceKnife` 和 `~/.local/share/SpaceKnife`），0.4.0 接着用。窗口自己的文件（主题、WebView 的数据）换了位置，不再放在 Electron 的配置文件夹里。<!-- TODO: confirm 标签、类别文件的格式与 0.3.x 完全兼容 -->
- **快照换了新格式**：0.4.0 存的快照是新格式（第 3 版）；0.3.x 存的快照 0.4.0 打不开，也不会出现在「最近」和对比列表里。旧文件仍留在 `snapshots` 文件夹里，不会被删除；重新扫描一次就有新快照。

### 已知限制

- 都还没有代码签名或公证（macOS 版是 ad-hoc 签名）；deb、rpm 还没在干净的 RHEL 9 / Ubuntu 22.04 上测过。
- 0.3.x 不会自动更新到 0.4.0，需要手动下载一次（见上文）。
- 0.3.x 的快照不能在 0.4.0 里打开或对比。
- macOS 的 dmg 和 deb / rpm 仍没有「无缝更新」：卡片会打开磁盘映像或安装包。
- ARM 便携版只在 GitHub 的 ARM 运行器上构建和测试过，还没在 ARM 真机上试过；安装包只有 x64。
- WinBtrfs 盘上两个只差大小写的文件夹，从其中一个（或它里面的文件夹）开始扫描，到达的是另一个，资源管理器和复制出去的路径也一样；请扫描包含两者的文件夹。
