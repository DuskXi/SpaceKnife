# 国际化（M7.5）

界面有两种语言：简体中文（源文本，写在代码里）和英文。设置「常规 › 界面语言」：跟随系统 / 简体中文 / English，切换后立即生效，不需要重启。

## 1. 原则

- **中文原文就是消息 id**（gettext 风格）：代码里照常写中文，用翻译函数包起来；英文写在词表里，键是一字不差的中文原文。
- **在显示的那一刻翻译**，不在导入时翻译：语言可以在运行中切换。
- 一条消息是一句完整的话，可变部分用 `{name}` 占位，**不要拼接**（中英文语序不同）。
- 测试按中文跑（后端 `conftest.py` 设 `SPACEKNIFE_LANGUAGE=zh-CN`，vitest 的 `test-setup.ts` 设中文），断言里写中文原文。

## 2. 后端（`spaceknife/i18n.py`）

```python
from ..i18n import _, tr, Texts

_("开始扫描")  # 当前语言的文本
tr("已导出 {n} 项", n=3)  # 翻译后再 str.format
TEXT = Texts({"busy": "扫描进行中"})  # 模块的文案表：每次读取时翻译
plural(n, "{count} 个快照", "1 snapshot", count=n)  # 英文的单数单独给出（中文没有单复数）
raise RpcError(code, TEXT["busy"])
```

- f-string 里不能有中文：改成 `tr("…{name}…", name=…)`。
- 模块里已经把 `_` 当作占位变量用时，改用 `tr`（被遮蔽的 `_` 不会翻译）。
- 「登记过的定义」在显示时统一翻译，文本本身不用包：设置项 `S(...)`（`settings.meta()`）、命令面板 `C(...)`。
- 写在声明处、中英成对的文案（`T("中文", "English")`、`Text(zh=…, en=…)`、TOML 的 `{ zh = "…", en = "…" }`）不进词表：插件和内置插件（`plugins/builtin/`：导出模板和格式的标题、洞察规则的 `i18n.en`）都这样写，`i18n_check` 把 `T` / `Text` 当作已翻译。插件的写法见 [plugin-dev.md](plugin-dev.md)「文案」，`plugin check` 检查缺英文和占位符不一致。
- 只是长得像文字的数据（搜索同义词、过滤别名、SpaceSniffer 的名字）在行尾写 `# i18n: ignore`。
- 开发者日志（loguru 的 debug / info）用英文或保持原样；用户看得到的（错误、事件、说明、状态）都要翻译。
- 词表：`spaceknife/locales/en/<区域>.json`，按区域分文件，加载时合并。

### 语言从哪里来

`general.language` = `system` | `zh-CN` | `en`；`system` 按顺序取：

1. `SPACEKNIFE_LANGUAGE`（强制，测试与诊断用）
2. `SPACEKNIFE_SYSTEM_LOCALE`（Electron 启动后端时传入它看到的系统界面语言）
3. Windows `GetUserDefaultUILanguage`；macOS `AppleLanguages`
4. `LANGUAGE` / `LC_ALL` / `LC_MESSAGES` / `LANG`

任何中文 locale（含繁体）都用简体中文，其他都用英文。解析结果放在 `SettingsState.language` 里推给前端。命令行（`spaceknife run` 等）读用户设置；提权的扫描助手是独立进程，跟随系统语言。

## 3. 前端（`renderer/src/lib/i18n.ts`）

```tsx
import { t } from "@/lib/i18n";

<button title={t("关闭标签")}>{t("关闭")}</button>
toast(t("已导出 {n} 项", { n }));
```

- JSX 文本写成 `{t("…")}`，属性写成 `title={t("…")}`。
- 带中文的模板字符串改成一条带占位符的 `t()`。
- 模块级的中文常量表改成在渲染时计算（函数或组件里），语言切换才会生效。
- 中英文结构确实不同时用 `byLang(中文, 英文)`（少用）。
- 只是数据的中文在行尾写 `// i18n-ignore`。
- 语言变化时 `store.lang` 改变，根组件重渲染，所有 `t()` 跟着变；树图标签随 `unitEpoch` 重画；后端给的文字（卷说明、类别名）重新获取。
- 词表：`renderer/src/locales/en/<区域>.json`。
- Electron 主进程只有几条文案（对话框标题、后端启动错误），自带中英对照（`main/text.ts`），随渲染进程通知的语言切换。

## 4. 过滤语法

- 关键字（`:class:`、`:hidden`、`:red`、`>1gb` 等）只有一套 ASCII 写法，两种语言下一样，便于分享和粘贴。
- 类别名两种语言都能用：英文界面里内置类别显示为 Video、Pictures、Audio、Archives、Programs、Documents、Other，中文名作为别名（`:class:视频` 与 `:class:Video` 等价）；用户改过名的类别按用户写的显示。
- 诊断信息按错误码在前端翻译。

## 5. 检查脚本

```bash
uv run python tools/i18n_check.py                  # 全部：硬编码中文 + 缺失的英文词条
uv run python tools/i18n_check.py --area electron --file apps/electron/src/renderer/src/shell/Toolbar.tsx
uv run python tools/i18n_check.py --missing        # 还没有英文的消息 id（JSON，可作为词表起点）
```

- 后端用 Python AST，前端用 `tools/i18n_scan_ts.mjs`（`@babel/parser`，需要 Node 和 `apps/electron/node_modules`）。
- 检查项：没包起来的中文、带中文的 f-string / 模板字符串、JSX 中文文本与属性、每条消息 id 都有英文、占位符一致、英文里没有残留中文、各词表之间没有冲突的译法。
- `packages/backend/tests/test_i18n.py` 在测试里跑同样的检查。
