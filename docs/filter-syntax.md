# SpaceKnife 过滤语法（SKF 1）

本文是过滤语言的规范。参考实现是 `packages/protocol/src/spaceknife_protocol/filter_syntax.py`（解析、规范化、格式化，纯 Python，后端和 Python 前端共用），求值在 `packages/backend/src/spaceknife/filter/`。Electron 前端通过协议方法 `filter.parse` 拿到同一份解析结果。

## 0. 设计原则与五条性质

**合理兼容 SpaceSniffer。** SpaceSniffer 2.0.5.18 合理的行为照搬；不合理的行为（实测出来的前后矛盾、静默忽略、与位置有关的结果）改成更合理的设计，并在第 9 节逐条列出。实测方法见 9.1。

语法满足以下五条性质，每条都有对应的自动化测试（第 11 节）：

| 性质 | 定义 | 怎么保证 |
|---|---|---|
| 全覆盖性 | 任何字符串都有确定的结果：要么是一组条件，要么是带位置的诊断；解析从不抛异常 | 条件分类规则覆盖所有输入（2.4）；随机字符串性质测试 |
| 无歧义性 | 每个字符串只有一种解析 | 条件按首字符和是否含 `<` `>` 唯一分类；每个单位、前缀只有一个含义（`m` 在运算符前是「修改时间」，在数字后是「分钟」，位置不同，不会冲突） |
| 规范唯一性 | 每个表达式有且只有一个规范形式；写法不同、含义按第 6 节规则相同的表达式，规范形式相同 | 规范形式由「规范化条件树」（6.1）唯一决定，格式化是它的函数 |
| 幂等性 | `canonical(canonical(x)) == canonical(x)` | 性质测试 |
| 完整性 | 每个规范化条件树都能写出来：`parse(canonical(x))` 的条件树等于 `x` 的；扫描器记录的每种属性（名称、所在文件夹、两种大小、三种时间、11 种属性、4 种标签、类别）都有对应写法；四种比较 `<` `<=` `>` `>=` 都可用；任何文件名都能按字面匹配（引号和转义，3.1） | 性质测试；第 3 节 |

规范形式用于去重（「最近过滤」）、缓存和测试；界面上的条件胶囊由规范化条件树生成（6.4），输入框里始终保留用户的原文。

## 1. 速览

| 写法 | 含义 |
|---|---|
| `*.mp4;*.mkv` | 名称是 mp4 或 mkv |
| `*.jpg;>100kb;>2weeks` | jpg，且占用大于 100 KB，且修改于两周之前 |
| `>1gb;<10gb` | 占用在 1 GB 和 10 GB 之间 |
| `s>=1mb` | 逻辑大小至少 1 MB |
| `m<10min` | 最近 10 分钟内修改过 |
| `c>1y` | 创建于一年之前 |
| `\temp` | 位于名为 temp 的文件夹中（任意一级） |
| `\|*.exe;\|*.dll` | 除 exe、dll 以外的所有文件 |
| `:attr:h-s` | 隐藏但不是系统文件 |
| `:red;:yellow`、`:tag:r+y` | 带红色或黄色标签 |
| `:class:视频`、`:class:Video/Movies` | 视频类文件 |
| `"a;b.txt"` | 名字就叫 `a;b.txt` 的文件 |

## 2. 文法

### 2.1 字符与位置

- 输入是任意 Unicode 字符串。空白指 Unicode 空白字符（Python `str.isspace()`）。
- 协议里的所有位置（token、诊断、未完成条件、补全区间、光标）都以 **UTF-16 码元**计，与三端文本框一致。

### 2.2 切分

表达式按 `;` 切分成**段**，但引号内的 `;` 不切分。引号只在段的主体开头才起作用（主体在可选的空白、`|`、`\` 之后）。每段去掉首尾空白；空段忽略。全部为空的表达式表示「不过滤」。

### 2.3 EBNF

关键字、前缀、单位、标签、属性一律不区分大小写；`ws` 表示零个或多个空白。

```ebnf
expression = segment , { ";" , segment } ;
segment    = ws , [ condition ] , ws ;
condition  = [ "|" , ws ] , body ;
body       = folder | keyword | quoted | compare | bare ;           (* 分类见 2.4 *)

folder     = "\" , ws , ( quoted | bare ) ;
keyword    = ":" , ( tagword | valued ) ;
tagword    = "red" | "yellow" | "green" | "blue" | "all" ;
valued     = "class:" , ws , classname
           | "tag:" , ws , taglist
           | ( "attr:" | "attrs:" ) , ws , attrlist ;
taglist    = tagitem , { ws , ( "+" | "-" ) , ws , tagitem } ;
tagitem    = "red" | "r" | "yellow" | "y" | "green" | "g" | "blue" | "b" | "all" ;
attrlist   = attrterm , { ws , ( ( "+" | "," ) , ws , attrterm | "-" , ws , attrname ) } ;
attrterm   = [ "-" , ws ] , attrname ;
classname  = 任意非空文本（到段尾，首尾空白忽略）;

compare    = [ prefix , ws ] , op , ws , number , ws , unit ;
op         = "<" | ">" | "<=" | ">=" ;
number     = digit , { digit } , [ "." , digit , { digit } ] ;    (* digit 为 ASCII 0–9 *)
prefix     = sizeprefix | ageprefix ;                               (* 表见 3.3、3.4 *)
unit       = sizeunit | timeunit ;

quoted     = '"' , { qchar } , '"' ;
qchar      = "\" , 任意字符 | 除 '"' 与 "\" 外的任意字符 ;
bare       = 不含 ";" "\" "|" "<" ">" 的非空文本 ;
```

### 2.4 条件分类（确定性）

去掉首尾空白和开头的 `|`（及其后的空白）之后，按下面的顺序取第一条成立的规则：

1. 以 `\` 开头：文件夹掩码；
2. 以 `:` 开头：关键字条件（标签、属性、类别）；
3. 以 `"` 开头：带引号的名称掩码；
4. 含有 `<` 或 `>`：大小或时间比较；
5. 其他：名称掩码。

因此 `=1mb`、`500mb` 都是名称掩码（`=` 和数字都可以出现在文件名里），条件胶囊会显示为「名称 =1mb」。

## 3. 条件

条件只对**文件项**判定（目录以外的条目：普通文件、符号链接、其他特殊文件）。目录本身从不匹配；目录里只要含有匹配的文件，就处于「含匹配」状态。

### 3.1 名称掩码

- 与**完整文件名**（含扩展名）做通配匹配：`?` 匹配恰好一个字符（Unicode 码位），`*` 匹配任意个（含 0 个）。`mp4` 只匹配名字就叫 mp4 的文件，要包含匹配得写 `*mp4*`。`*.*` 要求名字里有点，所以不匹配 `README`。
- 不区分大小写：掩码先转成小写；掩码字符 p 与文件名字符 x 匹配，当且仅当 x 属于 {p、p 的小写、p 的大写、p 的标题大小写}（只取单个字符的结果）。各平台规则相同。
- 引号形式：`"…"` 内部的 `;`、首尾空白、`|` `<` `>` 都按字面处理；`\` 转义下一个字符：`\*`、`\?` 表示字面的星号和问号，`\"` 表示引号，`\\` 表示反斜杠。通配符 `*` `?` 在引号里依然有效。这样任何文件名（包括 Linux 上含 `;`、`*`、`\` 的名字）都能按字面匹配。
- 不带引号的掩码里不能出现 `\`（报 `backslash_in_mask`），也不能出现 `|` `<` `>`（报 `bad_char`）；需要时用引号。

### 3.2 文件夹掩码

- `\掩码`：文件所在的任意一级文件夹的名字与掩码匹配（规则同 3.1）。参与匹配的文件夹是**扫描根**以及从扫描根到文件所在文件夹之间的每一级。扫描根按它自己的名字参与（扫描 `D:\Photos` 时是 `Photos`）；盘符根或文件系统根（`C:\`、`/`）的名字为空，只有 `*` 能匹配它。扫描根以上的路径不参与。
- 开头的 `\` 只是开关符，不表示根；`\` 后面的空白忽略。
- 命中正向文件夹掩码的文件夹在树图里以粗体标题显示。

### 3.3 大小

`[前缀] 运算符 数字 单位`，比较的是文件的整数字节数。

| 前缀 | 比较对象 |
|---|---|
| （无）、`d`、`disk`、`disksize`、`clustersize` | 占用大小（分配的簇） |
| `s`、`size`、`filesize`、`logicalsize` | 逻辑大小（文件长度） |

| 单位 | 字节 |
|---|---|
| `b` | 1 |
| `kb`、`kib` | 1024 |
| `mb`、`mib` | 1024² |
| `gb`、`gib` | 1024³ |
| `tb`、`tib` | 1024⁴ |
| `pb`、`pib` | 1024⁵ |

- 进制固定为 1024，不受显示设置影响。大小单位一律以 `b` 结尾，因此单独的 `k`、`g` 不是单位（报 `unknown_unit`，候选里列出 `kb` 等）；单位不能省略（`>500` 报 `missing_unit`：不带单位就分不清是大小还是时间）。
- 运算符是严格的数学含义：`>` 大于，`>=` 大于等于，`<` 小于，`<=` 小于等于。
- 数字可以带小数（`1.5gb`）。阈值是精确的有理数 x，按运算符换算成整数界，结果对整数大小精确成立：`>x` ⇔ `≥ ⌊x⌋+1`，`>=x` ⇔ `≥ ⌈x⌉`，`<x` ⇔ `≤ ⌈x⌉−1`，`<=x` ⇔ `≤ ⌊x⌋`。
- 上限 2⁶² 字节，超出报 `out_of_range`。

### 3.4 时间

`[前缀] 运算符 数字 单位`。比较的是**年龄** = 现在 − 时间戳（秒）。`<N` 表示 N 以内（更新），`>N` 表示早于 N 之前（更旧）。

| 前缀 | 时间戳 |
|---|---|
| （无）、`m`、`modify`、`modified` | 修改时间 |
| `c`、`create`、`created` | 创建时间 |
| `a`、`access`、`accessed` | 访问时间 |

| 单位 | 秒 |
|---|---|
| `s`、`sec`、`secs`、`second`、`seconds` | 1 |
| `m`、`min`、`mins`、`minute`、`minutes` | 60 |
| `h`、`hr`、`hrs`、`hour`、`hours` | 3600 |
| `d`、`day`、`days` | 86 400 |
| `w`、`wk`、`wks`、`week`、`weeks` | 7 天 |
| `mon`、`month`、`months` | 30 天 |
| `y`、`yr`、`yrs`、`year`、`years` | 365 天 |

- 月、年是固定长度，与日历无关，任何时刻含义相同。
- 时间戳未知的文件（例如 Linux 上的创建时间）不满足任何时间条件，取反后也不满足（见第 4 节）。
- 含时间条件的过滤会随时间推移重新求值（`m<10s` 用来看实时改动）。
- 前缀和单位必须同类：`s<5d`、`m>1mb`、`d<5d` 报 `unit_mismatch`。
- 上限 1000 年。

### 3.5 属性

`:attr:` 或 `:attrs:` 后面跟属性列表。`+` 或 `,` 表示「同时具备」，属性前的 `-` 表示「不具备」，`-` 也可以直接充当分隔符：`:attr:a+h-s` 与 `:attr:a,h,-s` 相同（归档、隐藏、不是系统）。多个 `:attr:` 条件之间是「且」。

| 属性 | 简写 | 属性 | 简写 |
|---|---|---|---|
| archive | a | offline | o |
| system | s | temporary | t |
| readonly | r | notindexed | ni |
| hidden | h | sparse | sp |
| compressed | c | ads（alternatedatastream） | ads |
| encrypted | e | | |

当前平台不记录的属性不算错误，但会给出 `unsupported` 警告（第 10 节）。

### 3.6 标签

`:red` `:yellow` `:green` `:blue`，`:all` 表示任意标签。完整写法 `:tag:列表`：从第一项开始，`+` 加入颜色，`-` 去掉颜色，颜色可以缩写成 `r` `y` `g` `b`；`:tag:red+yellow` 是红或黄，`:tag:all-red` 是有标签但不是红。多个标签条件之间是「或」。文件夹上的标签由其中的所有项继承。

### 3.7 类别

`:class:类别名`，类别名到段尾为止，可以含空格和 `/`，首尾空白忽略，不区分大小写。按扩展名匹配：最后一个点之后的部分（名字以点开头时视为没有扩展名）。

| id | 名称 | 别名 |
|---|---|---|
| video | 视频 | Video、Videos、Movies、Video/Movies |
| image | 图片 | Image、Images、Picture、Pictures、Pictures/Images、Photos |
| audio | 音频 | Audio、Music、Audio/Music |
| archive | 压缩包/镜像 | 压缩包、镜像、Archive、Archives、Disk images、Archives/Disk images |
| exec | 程序/系统 | 程序、系统、Program(s)、Executable(s)、System files、Executables/System files |
| doc | 文档 | Document、Documents、Docs |
| code | 代码/开发 | 代码、开发、Code、Source code、Development、Dev（SpaceKnife 新增） |
| data | 数据/模型 | 数据、模型、Data、Datasets、Models、Databases（SpaceKnife 新增） |
| other | 其他 | Other、Others、Unclassified（不属于任何类别的文件） |

类别的扩展名列表来自「文件类别」设置（默认表在 `packages/protocol/src/spaceknife_protocol/classes.py`，包含 SpaceSniffer 的全部默认扩展名）。`ts`、`mts` 同时在视频和代码里，按文件大小归入其中一个（`spaceknife.classes.STREAM_SPLITS`：16 MiB 以上，或 1 MiB 以上且大小是整数个传输流包——`ts` 188 字节、`mts` 192 字节——算视频，其余算代码）；只看大小，不读内容。不存在的类别名报 `unknown_class`，并列出候选。

## 4. 取反

条件前的 `|` 表示取反，`|` 后面的空白忽略。

- 名称、类别、文件夹、标签、属性条件取反表示**排除**满足它的文件。
- 大小、时间条件取反表示**反向区间**：`|>1mb` ≡ `<=1mb`，`|<5d` ≡ `>=5d`。因此取反的时间条件同样不匹配时间戳未知的文件。

## 5. 组合语义

记扫描树中的文件项集合为 F。对 f ∈ F：

- folders(f)：扫描根（按 3.2 的名字）及其下直到 f 所在文件夹的每一级文件夹；
- tags*(f)：f 自己和 folders(f) 中各文件夹的标签的并集。

把正向条件分组：W = 名称掩码 ∪ 类别（「是什么」），P = 文件夹掩码（「在哪里」），T = 标签颜色的并集，R = 大小、时间区间，A = 属性条件；N = 取反的名称、类别、文件夹、标签、属性条件。f 匹配，当且仅当：

```
(W = ∅ 或 存在 w ∈ W 使 w(f))
且 (P = ∅ 或 存在 p ∈ P、d ∈ folders(f) 使 p(d))
且 (没有标签条件 或 tags*(f) ∩ T ≠ ∅)
且 对所有 r ∈ R：r(f)
且 对所有 a ∈ A：a(f)
且 对所有 n ∈ N：非 n(f)
```

即：同一组里的正向条件是「或」，不同组之间是「且」，区间条件之间是「且」（因此 `>1mb;<10mb` 是区间），取反条件是「且非」。条件的书写顺序和重复不影响结果。

匹配统计：匹配文件数、匹配的占用大小与逻辑大小按子树汇总到每个文件夹；硬链接的重复项计入文件数，但不重复计入大小。

## 6. 规范形式

### 6.1 规范化条件树

解析得到的条件按以下规则合并成规范化条件树（`FilterNormal`）：

1. 名称掩码转成小写；连续的通配符规整为「若干 `?` 后跟一个 `*`」（`*?*` → `?*`，`**` → `*`）；去重。
2. 类别按 id 去重（任何名称、别名都归到 id）。
3. 文件夹掩码同 1。
4. 正向标签取颜色并集；取反标签也取并集（`|:red;|:blue` = 「排除红或蓝」）。
5. 大小区间按（占用、逻辑）分别取交集；不起作用的下界（≤ 0 字节）去掉。
6. 时间区间按（修改、创建、访问）分别取交集。
7. 正向属性条件合并为一组「必须具备」和一组「必须不具备」。
8. 取反的属性条件各自保留、去重；永远不成立的条件（既要又不要同一属性）取反后恒成立，去掉。

不做的化简（这些表达式的规范形式不同，尽管在某些数据上可能选中相同的文件）：通配符之间的包含关系（`*` 与 `*.txt`）、类别与扩展名的重合（`:class:video` 与 `*.mp4;…`）、空区间（`>10mb;<1mb`）与其他永不成立的条件。

### 6.2 拼写规则

规范文本由规范化条件树唯一决定：

- 顺序：名称、类别、文件夹、标签、大小（占用、逻辑）、时间（修改、创建、访问）、属性，然后依次是取反的名称、类别、文件夹、标签、属性。同类内部：掩码按码位排序，类别按类别表顺序，取反属性按文本排序。条件之间用 `;` 连接，不加空格。
- 名称掩码：能不加引号就不加；需要时（含 `;` 或转义，首尾有空白，以 `|` `\` `:` `"` 开头，含 `|` `<` `>`）写成引号形式，`"` 写作 `\"`。
- 类别写作 `:class:<id>`。
- 标签：四色齐全写 `:all`，一色写 `:red`，多色写 `:tag:red+yellow`（按红、黄、绿、蓝的顺序）。
- 属性：`:attr:` + 必须具备的属性简写（按 3.5 表的顺序，用 `+` 连接）+ 每个必须不具备的 `-简写`。
- 前缀：占用和修改时间不写前缀，逻辑大小写 `s`，创建时间 `c`，访问时间 `a`。
- 单位：`b kb mb gb tb pb`；`s min h d w month y`。
- 界：下界 lo 可写成 `>(lo−1)` 或 `>=lo`，上界 hi 可写成 `<(hi+1)` 或 `<=hi`。每个数都写成能整除它的最大单位（0 写成最小单位，视为最「整」）。两种写法中取单位更大的，相同时取严格的 `>` `<`。例：`|>1mb` → `<=1mb`；`>1.5gb` → `>1536mb`；`m<5d;m>1.5d` → `>36h;<5d`；`>0b` → `>0b`。

### 6.3 示例

| 输入 | 规范形式 |
|---|---|
| `*.TXT; *.jpg` | `*.jpg;*.txt` |
| `:attr:a,h,-s` | `:attr:a+h-s` |
| `:red;:yellow` | `:tag:red+yellow` |
| `> 1 mb ; < 10 MB` | `>1mb;<10mb` |
| `>1mb;>2mb` | `>2mb` |
| `MODIFIED<7200min` | `<5d` |
| `:CLASS:music` | `:class:audio` |
| `\| *.txt` | `\|*.txt` |
| `>=0b` | （空：选中全部文件） |

### 6.4 条件胶囊

侧栏「条件」块由规范化条件树生成，每组一个胶囊：名称（`或`）、类别（`或`）、文件夹（`或`）、标签（`或`）、大小与时间（每个字段一个，`> 500 MB 且 < 2 GB`，数值按显示设置换算）、属性（「有 a、h，没有 s」）、排除（取反条件）。光标处未完成的条件显示为虚线胶囊（第 7 节）。

## 7. 编辑中的表达式

解析时可以带上光标位置：

- **未完成条件**：光标所在的条件如果只是「还没写完」，就不报错、不参与求值，结果中给出 `pending`（类别 + 区间），胶囊显示为「类名 选择中…」。「还没写完」包括：只有 `|`、`\`、`:` 或运算符；`:class:` `:tag:` `:attr:` 后面为空；列表以 `+` `,` `-` 结尾；数字后面还没有单位，或单位、关键字、类别名、标签、属性只写了一个合法写法的开头（`>5mo`、`:cla`、`:class:Vi`）；引号未闭合；小数点后还没有数字。光标不在它上面时，同样的写法按错误处理。
- **补全上下文**：`completion` 给出上下文（`keyword` `class` `tag` `attr` `unit` `prefix`）、要替换的区间、已输入的部分和候选。候选按输入前缀筛选：类别给显示名称，属性给全名，单位按前缀限定为大小或时间单位，空段给常用开头。

含错误的表达式不生效：界面保持上一次有效的结果，并提示第一个错误（UI-W3-15）。

## 8. 诊断

每条诊断带错误码、出错片段与所在条件的 UTF-16 区间、出错的原文和可用的值（`expected`）。文案由前端按错误码本地化。

| 错误码 | 含义 | 例 |
|---|---|---|
| `incomplete` | 条件缺少必需的部分 | `\|`、`\`、`:`、`>`、`:class:`、`""` |
| `unterminated_quote` | 引号没有闭合 | `"abc` |
| `text_after_quote` | 闭合引号后还有内容 | `"abc"x` |
| `bad_escape` | 引号内末尾的 `\` | `"abc\` |
| `backslash_in_mask` | 不带引号的掩码里有 `\` | `\temp\x` |
| `bad_char` | 不带引号的掩码里有 `\|` `<` `>` | `a\|b`、`\a>b` |
| `unknown_keyword` | 未知关键字 | `:foo` |
| `unknown_class` | 未知类别 | `:class:nosuch` |
| `unknown_tag` | 未知标签 | `:tag:purple` |
| `unknown_attr` | 未知属性 | `:attr:z` |
| `bad_list` | 列表格式不对 | `:attr:h++r`、`:tag:+red` |
| `unknown_prefix` | 未知前缀 | `x>1mb` |
| `bad_operator` | 不是 `<` `>` `<=` `>=` | `=>1mb`、`<>1mb` |
| `bad_number` | 数字不合法 | `>abc`、`>.5mb`、`>1,5mb`、`>-1mb` |
| `missing_unit` | 缺少单位 | `>500` |
| `unknown_unit` | 未知单位 | `>500xb`、`d<16k` |
| `unit_mismatch` | 前缀与单位不同类 | `s<5d` |
| `out_of_range` | 数值超出上限 | `>99999999pb` |
| `unsupported`（警告） | 合法，但当前平台不记录这项属性或时间 | Linux 上的 `c<5d` |

多个条件各自报错，一个条件出错不影响其他条件的解析。

## 9. 与 SpaceSniffer 2.0.5.18 的关系

### 9.1 实测方法

`tools/spacesniffer_oracle.py` 用 SpaceSniffer 的命令行（`scan <目录> filter <表达式> export "Simple file list" <文件> autoclose`）对一个精确控制大小、时间、属性、类别和文件夹名的测试目录（`packages/backend/tests/filter_fixture.py`，16 个文件，外加一个用于区分进制和月、年长度的小目录）逐条求值。SpaceSniffer 运行在一个从不显示的独立桌面上；表达式非法时它会弹出「Filter contains errors」，工具读取弹窗原文后结束进程。共 170 条探针，结果在 `packages/backend/tests/data/spacesniffer_filter_oracle.json`，由 `test_filter_compat.py` 逐条回放。

### 9.2 扩展（SpaceSniffer 判为非法，SpaceKnife 赋予含义）

| 编号 | 内容 | SpaceSniffer |
|---|---|---|
| E1 | 小数：`1.5gb`、`m>1.5d` | Bad size or date specifier |
| E2 | `>=`、`<=` | Bad size or date specifier |
| E3 | 单位拼写补齐：`tb` `pb` `kib`…、`minute` `second` `mon` `hr` `wk` `yr` 等 | 只接受一个前后不一致的子集：`minutes` 可以、`minute` 不行，`hour` 可以，`tb` 不行 |
| E4 | 类别的中文名、别名和 id：`:class:Pictures`、`:class:视频`、`:class:video` | Bad file class name |
| E5 | 带引号的掩码与转义：`"a;b.txt"`、`"x\*y"` | 引号被当成名字的一部分（Windows 文件名不能含引号，永远不匹配） |

### 9.3 有意的差异（SpaceSniffer 合法，但行为不合理）

| 编号 | SpaceKnife | SpaceSniffer 的实测行为 | 理由 |
|---|---|---|---|
| D1 | `>` `<` 是严格比较 | `>` 实为 ≥、`<` 实为 ≤：`>0b` 选中 0 字节文件，`s>4000b;s<4000b` 选中 4000 字节的文件 | 运算符应当名副其实；需要包含边界时用 `>=` `<=`（E2） |
| D2 | 取反的大小、时间条件是反向区间 | `\|>1mb`、`\|<5d` 被静默忽略（选中全部） | 静默忽略用户写下的条件不可接受 |
| D3 | 同侧的多个界取交集：`>1mb;>2mb` = `>2mb` | `>1mb;>2mb` 的结果等于 `>1mb` | 区间条件之间一律是「且」，不应因写法不同而改变 |
| D4 | `\|`、`\` 后面的空白忽略 | `\| *.txt` 排除以空格开头的名字（结果是全部）；`\ temp` 寻找名为「 temp」的文件夹 | 与 `;` 两侧空白忽略的规则一致；以空白开头的名字用引号写 |
| D5 | 表中所有前缀拼写都有效 | `created<5d` 不报错但什么都不匹配，而 `create<5d`、`accessed<5d` 正常 | 明显的缺陷 |
| D6 | 扫描根按自己的名字参与文件夹掩码，其上的路径不参与 | 扫描根以完整路径参与：测试目录位于 `%TEMP%` 下，`\*temp*` 因此匹配了所有文件，而 `\fixture`（扫描根的名字）一个都不匹配 | 结果不应取决于从哪里开始扫描 |
| D7 | 永远不可能匹配的写法报错：`\temp\x`、`:foo`、不带引号的掩码含 `\|` `<` `>` | 当作普通名字，静默返回空结果 | 让用户立刻知道写错了 |

### 9.4 数据层面的差异（不属于语法）

- NTFS 上不超过 512 字节的小文件常驻在 MFT 中，SpaceKnife 报告的占用为 0；SpaceSniffer 按至少一个簇计算。兼容性测试在比较前把占用换成 SpaceSniffer 的口径，只比较语法和组合语义。
- 备用数据流（ads）还没有采集，`:attr:ads` 目前不匹配任何文件，并给出 `unsupported` 警告。

### 9.5 实测确认、照搬的行为

`;` 分隔且两侧空白忽略，空段忽略；关键字、前缀、单位不区分大小写；`>1 mb`、`<5 d` 这类运算符与数字、数字与单位之间的空白；进制为 1024（1010 字节的文件不满足 `s>1kb`）；`m` 是分钟（`>1m` 选中一天以前修改的文件）；1 月 = 30 天、1 年 = 365 天（30.5 天的文件满足 `>1month`，365.5 天的满足 `>1y`）；单位不能省略（`>500` 非法）；单独的 `k` 不是单位（SpaceSniffer 自己帮助里的示例 `d<16k` 在 2.0.5.18 上也报错）；名称掩码是对完整文件名、不区分大小写的通配；`*.*` 要求名字里有点；名称与类别为「或」，文件夹掩码之间为「或」，各组之间为「且」；大小区间、不同字段的时间条件之间为「且」；`:attr:` 与 `:attrs:` 等价，全名与简写等价，`+` `,` 为「且」、`-` 为「非」，多个 `:attr:` 为「且」；`:red` `:tag:r+y` `:tag:all-red` `:all`；未知类别、标签、属性报错；名称、类别、文件夹、标签、属性的取反为排除；文件夹掩码匹配任意一级，`\*` 选中全部文件。

## 10. 平台差异

- 名称匹配在所有平台上都不区分大小写（与 SpaceSniffer 一致）。
- Windows 记录全部属性（ads 除外）。Linux、macOS 只记录 hidden（以 `.` 开头的名字）；其余属性条件给出 `unsupported` 警告，按「不具备」求值。
- Linux 不提供创建时间：`c` 条件给出 `unsupported` 警告，按时间戳未知求值（3.4）。
- 后端通过 `filter.vocab` 下发本平台的类别表和不支持的属性、时间，解析器据此给出警告。
